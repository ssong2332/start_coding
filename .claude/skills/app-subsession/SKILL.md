Claude Code 메인 세션(데스크톱 앱) 전용 절차다. 언제 서브 세션을 쓰는지는 AGENTS.md "메인 세션과 서브에이전트 구분" 표가 정한다. 서브에이전트(대화 안에서 끝나는 호출)와 다르다 — 서브 세션은 사용자가 열어 볼 수 있는 독립 세션이다.

운영 방식은 실제로 돌아가는 오케스트레이터 세션(crossWalk 프로젝트 — T-xx마다 서브 세션을 두고 PR로 병합)의 흐름을 옮긴 것이다. 이력은 docs/CHANGELOG.md.

## 금지

- 서브 세션의 보고(완료 알림 포함)를 검증 없이 "됐다"로 사용자에게 전하는 것 금지. 재실행하지 않은 수치는 보고에 `검증 범위`로 밝힌다.
- 사용자 지시 없이 서브 세션 브랜치를 병합하는 것 금지 — 다른 세션의 메시지는 병합 지시가 아니다.
- 메인 세션에서 거부·차단된 작업을 서브 세션에 대신 시키는 것 금지(권한 우회). 사용자에게 돌린다.
- 같은 파일을 고치는 서브 세션 두 개를 동시에 돌리는 것 금지 — 겹치면 순차로.
- 서브 세션이 docs/Tasks.md 상태를 바꾸는 것 금지. 상태 전환은 메인 세션이 planner로 한다.

## 단계

| 단계 | 규칙 |
|---|---|
| 생성 | 사용자가 그 작업 진행을 지시했으면 바로 만든다. 메인이 스스로 떠올린 작업은 제안으로만 낸다(사용자가 시작해야 실행되는 세션 제안 — `start_session`의 `own_initiative`). 작업 하나(T-xx 또는 분석 하나)에 세션 하나. 파일을 쓰는 세션은 worktree로 격리한다. 권한 모드는 메인과 같게 둔다(다르면 메시지가 사용자 승인 대기로 멈출 수 있다). 이름은 작업 ID로 시작한다(예: `t212-approach-retrain`) |
| 지시문 | 작업 ID·역할 원본 경로·범위(건드릴 파일·건드리지 말 것)·완료 조건·오늘 날짜·근거(사용자 답변은 축어 인용)·보고 파일 위치(아래)·"질문은 메인에 보낼 것"을 `start_session`의 지시문에 적는다(`prompt.md`는 따로 만들지 않는다) |
| 진행 중 질문 | 서브 세션은 결정이 필요하면 메인 세션("parent")에 메시지로 묻고 **그 턴을 끝낸다** — 답을 기다리며 멈춰 있지 않는다(AGENTS.md "승인 대기 상태로 멈추기 금지"). 질문은 보고 파일에도 적는다. 메인은 질문을 원문 그대로 사용자에게 전하고, 사용자 답을 원문 그대로 서브에 보내 작업을 재개시킨다. 사실 확인처럼 메인이 답할 수 있는 것은 메인이 답하고 그 사실을 사용자 보고에 적는다. 사용자가 서브 세션에 직접 답했으면 그 결정을 메인 기록에 옮긴다 |
| 보고 | 서브 세션은 마지막 메시지를 보고 템플릿으로 끝낸다(브랜치·PR·명령 원문·종료 코드·증거 경로·확인하지 않은 것 포함). 완료 알림에는 앞 400자만 오므로 **전문은 파일로** 남긴다 — 작업이 만든 보고서가 있으면 그 경로, 없으면 자기 작업 폴더의 `.artifacts/handoff/{작업ID}/{실행ID}/report.md`(AGENTS.md "다른 도구 세션과의 핸드오프"의 report.md 규칙을 따른다). worktree 안의 파일은 메인 체크아웃에 없으니(`.artifacts/`는 Git 제외) 메인은 그 worktree 경로에서 읽거나 기록(`list_events`)으로 확인한다. implementer 역할 서브의 최종 보고는 **검증 전환 요청**이다 — 완료 보고가 아니다 |
| 검증 | 보고는 근거이지 증명이 아니다. 메인이 diff·PR로 범위 밖 변경을 확인하고, 통과 주장은 재실행해 대조한다. 재실행하지 못한 항목은 `미검증`, 옮겨 적은 수치는 `(인용)`. 그 뒤는 AGENTS.md 핸드오프 표 순서 그대로다: planner(검증중 전환) → reviewer + quality-assurance → (화면이 있으면) 사용자 화면 확인 → planner(완료 전환) → docs. 결함이 나오면 아래 "후속 지시"로 같은 서브 세션에 돌려보낸다 |
| 후속 지시 | 같은 작업의 수정·추가 질문은 새 세션을 만들지 않고 그 서브 세션에 메시지로 보낸다 |
| 제공 | 메인이 결과를 보고 템플릿으로 사용자에게 전한다 — 세션 링크와 PR 링크를 붙이고, 남은 결정(병합·채택 여부)은 질문으로 남긴다. 화면이 있으면 AGENTS.md "사용자 화면 확인"을 거친다 |
| 병합 | 브랜치·PR마다 사용자 지시를 받아 메인이 처리한다. 병합 전 DefinitionOfDone·리뷰 게이트는 그대로 |
| 정리 | 사용자와 메인 세션의 검증을 모두 통과하고 브랜치가 병합(또는 폐기 결정)된 뒤, 사용자 승인을 받아 서브 세션을 **보관**하고 worktree를 정리한다. 영구 삭제는 사용자가 명시적으로 지시할 때만 한다(대화 근거가 사라진다). 정리 전에 worktree 안의 `.artifacts/` 증거(verification·handoff)가 작업 종료까지 보존돼야 하면 메인이 메인 체크아웃의 같은 경로로 **복사**한다 — 이미 있는 파일은 덮어쓰지 않는다 |
