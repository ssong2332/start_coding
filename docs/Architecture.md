## 실행환경 사전 확인 (기술 선택 전)

메인 세션은 기술 스택을 제안하거나 architect에게 설계를 맡기기 전에 아래 항목을 읽기 전용으로 확인하고, 확인한 값·명령 출력·사용자 답변 원문 또는 도구 목록을 architect에게 전달한다. 특정 도구에서만 가능한 기능을 모든 도구의 공통 실행 수단으로 가정하지 않는다. 이 표는 새 프로젝트에서 확인 결과로 채우는 양식이며, 확인 전에는 `미확인`을 유지한다. 설치·프로젝트 파일 변경·테스트 하네스 구축은 이 단계에서 하지 않는다.

| 확인 항목 | 읽기 전용 확인 방법과 전달할 근거 | 확인 결과 (새 프로젝트에서 갱신) |
|---|---|---|
| 실제 런타임·버전 | PRD 후보 기술의 실행 파일 위치와 버전을 읽기 전용 명령으로 확인하고 명령 원문·출력을 전달한다. | 미확인 — 프로젝트 실행 환경에서 후보 런타임을 확인해야 한다. |
| 설치 허용 여부 | 사용자 답변과 현재 실행 환경의 패키지 설치·네트워크 제약을 확인하고 허용 범위의 원문을 전달한다. 설치 가능 여부를 연결 성공이나 기억으로 추정하지 않는다. | 미확인 — 사용자 의사와 실행 환경 제약을 확인해야 한다. |
| 테스트 실행 수단 | 후보 테스트 러너의 설치·실행 가능 경로 또는 런타임 내장 테스트 기능을 읽기 전용으로 확인하고 명령·출력을 전달한다. | 미확인 — 후보 러너 또는 내장 기능을 확인해야 한다. |
| 브라우저 실물 확인 수단 (웹 UI인 경우) | 해당 도구에서 실제 화면을 열고 조작할 수 있는 브라우저 도구·앱·수동 확인 경로를 확인해 전달한다. 웹 UI가 아니면 `해당 없음 — 화면이 없는 프로젝트`로 기록한다. | 미확인 — 웹 UI 여부와 사용 가능한 확인 수단을 확인해야 한다. |

확인할 수 없는 항목은 `미확인 — {사유}; 확인 방법: {필요한 명령·도구·사용자 답변}`으로 남기고 가용하다고 단정하지 않는다. architect는 전달된 근거와 PRD에 맞춰 기술을 선택한다. 여기서 확인하는 것은 **수단의 가용성**이며, T-01은 선택한 러너로 스모크 테스트와 빌드·실행·테스트 명령이 실제 성공하는지를 별도로 검증한다.
