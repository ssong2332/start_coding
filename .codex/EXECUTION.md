# Codex 실행 결과 수집

업무 규칙은 AGENTS.md와 해당 .agents/roles/*.role.md를 따른다. 이 문서는 Codex 도구 차이만 다룬다.

## 실행 상태
현재 제공된 도구의 API 계약을 먼저 확인한다. 이름이 비슷한 API나 지원하지 않는 옵션을 추측하지 않는다.

| 관찰 | 처리 |
|---|---|
| exec_command가 session_id를 반환하고 종료 코드가 없음 | 같은 session_id로 write_stdin을 호출해 이어받는다. 명령을 중복 시작하지 않는다 |
| functions.exec가 Script running with cell ID를 반환 | 같은 cell_id로 functions.wait를 호출한다. 명령 session_id와 혼용하지 않는다 |
| 빈 출력 또는 실행 중 상태 | 완료로 판정하지 않는다. 실행 주체·cwd·명령·실행 ID와 최초·후속 출력을 유지한다 |
| 실행 종료 | 대상 프로세스의 실제 종료 코드와 전체 출력을 확인한다. 수집 명령의 성공으로 대신하지 않는다 |
| 종료 코드 0과 셸 진단문이 섞임 | 원문을 보존하고 명령 결과와 진단문을 구분해 보고한다. 조용히 삭제하거나 성공으로 단정하지 않는다 |
| 도구 오류·출력 누락·잘림 | 오류와 누락 범위를 보고하고 미검증으로 남긴다. 실행 중이면 기존 세션의 추가 출력을 확인한다. 재실행은 과거 원본의 복구가 아니다 |

## 증거 대조
- 검증된 명령 원문은 그대로 실행하고 출력 수집 방법은 별도로 기록한다.
- AGENTS.md의 보존 규칙에 따라 stdout·stderr 전체와 메타데이터를 저장한다. 도구가 합쳐서 반환하면 그 사실과 수집 범위를 명시한다.
- 보고 전에 저장된 실제 경로를 열어 명령·실행 주체·시각·cwd·종료 코드·테스트 수·실패 상세와 대조한다. 파일명이나 필드명을 추측하지 않는다.
- Red 원본을 수정 전에 확보했는지 확인한다. Green·회귀 및 다른 역할의 재실행은 각각 별도 증거다. 누락된 출력이나 다른 주체의 관찰을 직접 실행으로 바꾸지 않는다.
- 실행이 끝나기 전에 핸드오프가 필요하면 진행 중인 세션 식별자와 이미 수집한 범위를 전달한다. 동일 실행을 다른 역할에 중복 요청하지 않는다.
- 다음 역할에 실제 cwd·명령 원문·실행 상태·증거 경로·미해결 항목을 전달한다. 업무상 승인·인용·보고·핸드오프 규칙은 공통 원본을 따른다.

## 실행 준비와 명령 전달
- 작업 시작 시 .codex/DEVELOPMENT.md의 담당 역할 부분을 읽는다. UI 변경은 그 문서가 연결하는 FRONTEND.md를 적용한다.
- 현재 cwd·셸·런타임 경로/버전·검증된 명령·화면 도구를 확인한다. 다른 컴퓨터의 절대 경로나 과거 세션의 프로세스 상태를 그대로 재사용하지 않는다.
- 셸 초기화 진단이 섞이면 대상 명령의 상태와 분리한다. 기존 승인 범위에서 확인된 셸·런타임을 명시할 수 있으나, 권한 확대·새 설치·우회는 별도 허가를 대신하지 않는다.
- 검증된 명령을 바꿔야 하면 변경 이유를 먼저 밝히고 기존 원문과 새 실행 수단을 구분한다. 도구의 자동 권한 검토가 시간 초과했다고 대상 명령이 실행됐거나 안전성 문제로 거부됐다고 단정하지 않는다.
- 셸 명령은 코드로 취급한다. JSON 문자열화를 셸 인자 이스케이프로 사용하지 않는다. 긴 본문은 패치나 파일로 전달하고, Windows 명령 길이 제한을 피하도록 작업을 나눈다.
- UTF-8 텍스트는 인코딩을 명시해 읽고 쓴다. PowerShell 따옴표·보간과 로캘에 의존하지 않는다. Python 요약 출력이 필요하면 지원되는 환경에서 UTF-8 모드(-X utf8)를 사용한다. 인코딩 오류가 출력 요약에만 생겼다면 저장된 원본과 대상 프로세스 종료 코드부터 확인하고 테스트를 중복 실행하지 않는다.

## 로컬 서버와 브라우저
- 실행 중인 서버는 확인한 PID·cwd·주소·포트와 로그 위치를 유지한다. 같은 포트에 중복 시작하지 않고, 실패했을 때 무관한 프로세스를 종료하지 않는다.
- 서버 시작 명령의 반환만으로 준비 완료를 보고하지 않는다. 실제 리스너/응답과 브라우저 접속을 확인하고, HTTP 확인과 실제 화면 확인을 구분한다.
- Windows 백그라운드 프로세스는 사용자가 보이는 창을 요청하지 않았다면 숨김으로 실행한다. 종료·정리는 자기 실행의 식별자를 다시 확인하고 허용된 범위에서만 수행한다.
- 브라우저는 현재 제공된 API를 읽고 사용한다. URL·탭·뷰포트·실제 크기를 구분하며 사용자의 작성 내용을 잃는 재로드를 피한다. 임시 뷰포트·탭은 도구의 정리 규약에 맞춰 복구하고 결과 화면은 사용자가 볼 수 있게 남긴다.

## 결과 수집의 경계
- 수집기 stdout/stderr와 테스트 프로세스 stdout/stderr를 구분하고 명령은 실행 파일과 인자 배열까지 기록한다. 저장된 원본을 보존한 뒤 요약한다.
- 로그 파일 생성 성공, 검사기 기능 저하 상태, 설정 파싱 성공, 현재 앱에서의 실제 동작 성공은 서로 다른 결과다. 자동 로드나 새 세션 동작을 실행하지 않았다면 미검증으로 적는다.
